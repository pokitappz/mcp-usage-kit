Why request counts fail

One MCP operation can produce many HTTP requests.

Multi-round-trip calls and durable tasks add retries and polls around one result. UsageKit reads terminal protocol state instead of treating every request as another unit of work.

Per-request billing

Each protocol exchange is counted

12 requests12 charges

MRTR retries, task polls, and failed calls can all appear on the invoice.

Terminal-result billing

Only completed work is counted

12 requests1 charge

Intermediate states stay free. Task completion uses the originating tool's price and is deduplicated by task ID.

What the layer handles

Provider-grade accounting in one Tower layer.

The implementation covers the protocol cases that a request counter cannot distinguish.

RESULT

Terminal-result billing

Price the actual result. Interim input requests, discovery, subscriptions, JSON-RPC errors, and failed tasks remain free.

resultTypecompletebill once
TASK

Durable task attribution

Carry origin pricing through Redis, Valkey, PostgreSQL, or memory, then atomically claim completion across instances.

CACHE

Authorization-safe caching

Partition private entries by exact authorization context and rewrite JSON-RPC IDs when serving cache hits.

EXPORT

Failure-isolated exports

Aggregate usage off the hot path. Export failures retain quantity and idempotency identity without changing MCP responses.

LIMITS

Defensive limits

Bound request and response observation, reject duplicate security metadata, and fail toward not charging.

OBSERVE

Standard observability

Expose fixed-cardinality Prometheus text or register OpenTelemetry counters without exporting customer or tool identifiers.

VERIFY

Portable conformance suite

Reuse versioned JSON vectors to verify terminal delivery, free reasons, origin pricing, and idempotency in any language.

STRIPE

Billing event exporters

Start with structured logs or enable the optional Stripe exporter for pre-aggregated integer meter events.

cargo add mcp-usage-export --features stripe

    Use your own stack

    No gateway or platform account required.

    The crates run inside your MCP service and keep providers replaceable. Start in memory, add shared state when you scale, and export the same accounting decisions to the systems you already operate.

    Read the conformance contract →
    Shared state

    Redis, Valkey, and PostgreSQL

    Hashed identifiers, expiring records, first-writer attribution, and atomic completion claims for horizontal deployments.

    Telemetry

    Prometheus and OpenTelemetry

    Low-cardinality counters with no API keys, customer identifiers, tenant identifiers, methods, or tool names.

    Usage export

    Logs, Stripe, or your exporter

    A small object-safe exporter contract keeps billing providers off the request path and easy to replace.
